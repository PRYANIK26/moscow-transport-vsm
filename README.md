# На борту

Тренажёр для проводников: ситуации в 3D-вагоне, разговор с пассажиром, действия с предметами и разбор результата. Сценарии создаются и публикуются в редакторе на том же сайте.

Демо: https://fullstack-vsm.duckdns.org

## Возможности

- **Обучение:** курс из 12 ситуаций, отдельные тренировки, поиск и материалы.
- **Игра:** 3D-вагон, пассажиры, цели, инвентарь, общий или пошаговый таймер. Перезагрузка не начинает отсчёт заново.
- **Общение:** текст, запись по пробелу, распознавание речи и озвучка пассажира. На телефоне — экранные кнопки и горизонтальное положение.
- **Редактор:** дерево ситуаций и ответов, условия переходов, маршруты, настройка сцены, предметов, пассажиров и времени. ИИ-помощник готовит предложение для черновика.
- **Кабинет:** история, прогресс, достижения, профиль и аватар.
- **Рейтинг:** общий, сервис и безопасность; тестовые и зарегистрированные проводники.
- **Уведомления:** новые сценарии и достижения, фильтры, сортировка, страницы, удаление прочитанных и Web Push.
- **Администрирование:** роли и независимое включение разделов.

## Локальный запуск

Нужны Node.js 22.12+ и PostgreSQL 17. Команды предназначены для отдельной локальной копии проекта.

```bash
npm ci
cp .env.example .env
npm run db:up
npm run db:setup
npm run dev
```

Открыть http://127.0.0.1:5180. API работает на порту 4180. `npm run dev` запускает интерфейс, API и worker.

`db:up` запускает PostgreSQL на `127.0.0.1:55432`, данные — в `.runtime/pg`. Скрипт рассчитан на Linux и `/usr/lib/postgresql/17/bin`; другое расположение задаётся через `VSM_PG_BIN`. Для своей БД пропустите `db:up` и задайте `DATABASE_URL`. Остановка локальной БД: `npm run db:down`.

При первой настройке создаются публичные тестовые аккаунты:

| Роль | Email | Пароль |
|---|---|---|
| Проводник | student@vsm.demo | DemoTrain2026! |
| Автор | author@vsm.demo | DemoTrain2026! |
| Администратор | admin@vsm.demo | DemoTrain2026! |

Самостоятельная регистрация создаёт проводника. Для базы без демоданных задайте `DEMO_SEED=false` перед `db:setup`.

### Настройки

Значения задаются в `.env`; ключи в репозиторий не добавляются.

| Переменная | Назначение |
|---|---|
| `DATABASE_URL` | Подключение к PostgreSQL |
| `HOST`, `PORT` | Адрес и порт API |
| `WEB_ORIGIN` | Адрес интерфейса для проверки запросов |
| `API_PROXY_TARGET` | Адрес API для Vite |
| `YANDEX_API_KEY`, `YANDEX_FOLDER_ID` | Диалог и ИИ-помощник редактора |
| `YANDEX_SPEECHKIT_API_KEY` | Ключ SpeechKit; при отсутствии используется основной ключ |
| `YANDEX_MODEL`, `YANDEX_VOICE` | Модель и голос |
| `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT` | Web Push; одна пара ключей для API и worker |
| `LEADERBOARD_ALL_STUDENTS` | `true` — общий рейтинг всех проводников |

Без ключей Яндекса доступны предметные действия и локальные текстовые ответы; SpeechKit и ИИ-помощник требуют настроенного провайдера. Для микрофона и Push нужен HTTPS или localhost. Worker обрабатывает диалоги и уведомления.

## Новый сценарий

1. Войти автором, открыть редактор и создать сценарий: текстовый, 3D или маршрут.
2. Заполнить название и ситуации. Для 3D выбрать вагон, пассажира, точки и предметы.
3. Добавить ответы и действия, соединить шаги, настроить условия и исходы.
4. Задать время: общий лимит в минутах или отдельный лимит каждого активного шага.
5. Сохранить, проверить и опубликовать. Сценарий появится в обучении.

Сохранение черновика не меняет опубликованную игру. После публикации новые попытки используют новую версию; уже начатые продолжаются на прежней. Новое сочетание имеющихся действий не требует изменения кода. Новая 3D-модель или механика требуют доработки приложения.

ИИ-помощник: запрос → предпросмотр → применение в черновик → проверка → публикация. Модель не начисляет баллы и не завершает попытки самостоятельно.

## Устройство проекта

```text
apps/web/          React, Vite, Three.js, страницы и редактор
apps/api/          Fastify, движок, права, фоновые задачи и миграции
packages/shared/   Общие типы API
scripts/           Запуск, импорт контента и сборка документации
deploy/            Dockerfile и nginx
```

PostgreSQL хранит пользователей, публикации, попытки, дедлайны, результаты и очереди. Переходы, ограничения действий и баллы проверяет API. Повтор команды не создаёт повторный результат. Несколько экземпляров API и worker используют общую БД.

Разделы отключаются и в интерфейсе, и на сервере. Отключение игры сохраняет доступ к истории и достижениям; опубликованная игра работает без редактора. Уведомления не блокируют сохранение результата.

## API

57 операций описаны в `apps/api/src/openapi.ts`, включая фильтрацию и удаление уведомлений.

- `/api/docs/` — Swagger с выполнением запросов.
- `/api/docs/overview/index.html` — схемы и каталог методов.
- `/api/openapi.json` — контракт API.

```bash
npm run docs:build
npm run docs:check
npm run docs:test-api
```

Swagger использует сессию вошедшего пользователя. Права и проверки доступа сохраняются. Ресурсы поставляются локально; лицензии находятся в `apps/api/docs/swagger/`.

## Сборка и проверки

```bash
npm run typecheck
npm run build
npm run start:api
# В отдельных терминалах:
npm run start:worker
npm run preview:web
```

Сборка интерфейса — `apps/web/dist`. API запускается через `tsx`.

Серверные тесты: `npm test`. Интеграционные тесты меняют данные: используйте отдельную тестовую БД. В тестовых файлах указаны переменные и адреса тестовых баз. `docs:test-api` требует БД с `test` в имени.

Сохранены `test:e2e` и `test:editor`; часть браузерных тестов проверяет прежние экраны. Они не заменяют проверку текущего обучения и 3D-игры.

## Docker

```bash
docker compose up --build -d
```

Открыть http://127.0.0.1:5180. Compose запускает PostgreSQL, настройку БД, API, worker и nginx. Данные находятся в томе `pgdata`. Конфигурация предназначена для локального демо. Для внешнего размещения нужны домен, HTTPS, собственные пароли БД и резервное копирование. Проверка Docker-развёртывания описана в [инструкции](docs/deployment.md).

## Проверки и ограничения

Проверены серверные переходы и таймеры, права и модули, сохранение результатов, уведомления, редактор → публикация → 3D, возобновление игры, голосовые запросы и Swagger. Мобильное прохождение проверено в Chromium с эмуляцией touch. Микрофон и Push на физических Android/iOS требуют отдельной проверки.

Подтверждение email и восстановление пароля пока не подключены. Некорректный JSON-импорт может оставить пустой черновик; повторная публикация без изменений создаёт следующую версию. Перед использованием для аттестации учебные оценки должен проверить специалист.
